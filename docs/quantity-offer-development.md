# Quantity offers during Medusa tier discovery work

The existing product requests include `*variants.prices` alongside calculated prices. Grid cards and product details read ordinary tiers from their own selected variant. There is no separate offer request, server map, or per-variant environment configuration.

The existing variant helper accepts currency-matching ordinary prices with no rules or a matching region rule and a tax-inclusive calculated price. Unsupported rules/tax treatment, malformed data and missing tiers hide offers; ordinary product pricing remains available. Region/currency/tax policy remains owned by the existing storefront and Medusa.

Grid markup and product-detail buttons live directly in their respective views. Both use `getVariantPriceDisplay`, which now returns one display for a base price and additional displays for configured tiers. Passing a quantity resolves its total through the same helper. The existing `formatPrice` helper is unchanged. Each preview uses ordinary prices whose quantity ranges include the selected quantity. The calculated price participates only within its returned quantity range (or a matching ordinary price range); unresolved quantities retain the single-item price labelled “pr. stk.” rather than a guessed total. Single-item displays always use Medusa’s calculated amount. Override Price Lists (and unknown Price List types) suppress ordinary-tier previews; their calculated amount is used only within its known range. Only positive incremental savings produce comparison totals. Cart and checkout continue to use Medusa and existing actions.

Product queries also request `variants.prices.price_rules`. Grid and product-detail pricing pass the active region to the shared helper. The helper selects the ordinary price set for the matching `region_id` first, falling back to the general currency set only when no regional set exists. All offer thresholds and quantity prices then come from that selected set; prices from the two sets are not mixed. Missing rule details and unsupported rule attributes/operators still hide offers.

Forzudo Rojo in staging uses ordinary variant quantity prices. The Volume Discount Price List has been removed; ordinary variant prices are now the source of truth. The previously discussed Price List synchronizer is not part of this implementation. Reverify storefront and cart pricing after configuration changes.

Public Store product responses still omit Price List tiers: https://github.com/medusajs/medusa/issues/16836. In particular, raw ordinary tiers cannot reveal hidden quantity-specific price-list overrides. The current override guard only detects an override selected for the single-item calculation. It cannot detect an override that starts at a higher quantity. Such mixed configurations are unsupported: products using ordinary-tier previews must not also have hidden quantity-specific Price List overrides. This is a catalogue configuration constraint, not an enforced allowlist; production rollout remains tracked separately. Do not assume a future Price List response has the same structure or eligibility guarantees.

Run `pnpm test:unit --run`, `pnpm check`, and `PLAYWRIGHT_BASE_URL=http://localhost:5173 pnpm test:integration tests/quantity-offers.spec.ts` against a local preview using the staging catalog. The Forzudo tier browser tests use the real staging response without stripping Price List metadata. A separate Bag-in-Box fixture verifies non-bottle tier labels. Missing/rejected-tier fallbacks are also covered. No feature-specific environment variable is needed.
